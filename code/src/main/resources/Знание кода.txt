1. При изменении метода на makeGenericSound больше не получится вызвать myCat.makeSound() т.к контракт будет для класса
Animal, у которого такого метода нет

2. Такой метод public void makeSound(int numberOfSounds) не сможет сработать, т.к это не переопределение метода из родительского класса

3. В данном случае мы будем зависеть от конкретной реализации json-парсера - ObjectMapper, например метод может
не ограничиться выбрасыванием лишь ошибок IOException, если будет обновлена версия библиотеки. Также мы зависим от поведения
writerWithDefaultPrettyPrinter(), который задает формат "опрятного" Json.
